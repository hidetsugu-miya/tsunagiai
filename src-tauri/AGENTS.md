# つなぎAI: the Rust backend

This file is the part of the developer guide (`AGENTS.md` of the root) for `src-tauri/`: the modules and what `tsunagiai-mcp` offers.
Claude Code and other agents read it when they work under `src-tauri/`.

## Modules

The modules are in the library crate (`src/lib.rs`), and `main.rs` only calls `tsunagiai_lib::run()`.
Each service has its own module:

- `gmail.rs`, with `gmail/held.rs` (the opened threads held in memory for a reopen, M-2)
- `icloud.rs` (M-13, #1573, #1574): the iCloud accounts: `icloud_accounts`, `icloud_check` (an IMAP login with the kept App-specific password, then a logout), `icloud_add_account` (the login first; the password goes into the keychain and the row into `accounts.json` only when iCloud accepts it) and `icloud_remove_account`, with the IMAP over TLS (`async-imap`, `tokio-rustls`, `rustls-platform-verifier`) to `imap.mail.me.com:993`; and the reads of the mail, which `mail.rs` and `gmail::load_inbox` call: `inbox_threads` (the newest 50 mails of INBOX as thread rows, with the replies in Sent Messages) and `fetch_thread`; and the sync (#1575): `sync`, one round of the 10-second poll of the screen (`ENABLE QRESYNC`, `SELECT INBOX (CONDSTORE)`, and `UID FETCH ... (CHANGEDSINCE ... VANISHED)` only when the HIGHESTMODSEQ moved), with `inbox_threads` also giving the sync position. and the changes (#1576): `change`, which marks the INBOX mails of a thread read or unread or moves them to `Archive` or `Deleted Messages` and back (`UID COPY`, then `UID STORE +FLAGS (\Deleted)` and `UID EXPUNGE` of the same UIDs, since iCloud has no MOVE). `icloud/read.rs` runs the reads over an open session (`EXAMINE` and `BODY.PEEK` only, tested against a fake server on a local `TcpListener`), `icloud/sync.rs` decides and reads the difference (the position `{UIDVALIDITY}:{HIGHESTMODSEQ}`, `step` and `outcome` as pure functions, tested against a fake server that answers the commands it is given), `icloud/message.rs` reads a mail with `mail-parser` into `ThreadItem` and `ThreadDetail` (the same types as Gmail's), `icloud/modify.rs` runs the changes over an open session (`Move::route` as a pure function, tested against a fake server that really copies, flags and expunges), and `icloud/threading.rs` joins mails into threads (pure functions: Message-ID, In-Reply-To, References, the thread ID made from the root's Message-ID)
- `calendar.rs` (Google Calendar, the check of the candidates of free time of `calendar_show_slots`, C-6, and the lookup of other people with their weeks: `calendar_search_people` and `calendar_person_week`, C-9, #1556), `todoist.rs` (Todoist)

The modules shared by the services:

- `accounts.rs`: the list of accounts in `accounts.json` (an address and a kind, `gmail` or `icloud`, for each; a row that is only an address is a Gmail account, and a Gmail account is written that way still; `load` lists the Gmail addresses only, `load_accounts` lists every kind), and the atomic write of a settings file

- `mail_address.rs` (splits a From or To header into a name and an address, and works out who a reply goes to, M-10), `mail_send.rs` (builds the message of a new mail or a reply and sends it, the command `send_mail`; the files of M-12 go into it as `multipart/mixed`), `mail_attach.rs` (M-12: whether a file may be attached, and the dialog that picks files)
- `images.rs` (the images in HTML mail, with `images/macos.rs`, which fetches an external image with NSURLSession) with `image_senders.rs` (the senders whose external images are shown without asking)
- `disk_cache.rs` (the kept copies of the last calendar weeks that the screen draws first at startup; the mail list is no longer kept, #739)
- `markdown_patch.rs` (puts an edit of the rich Markdown editor into the original text by lines, A-26; the mail of M-10 and the Slack posts of S-6 and S-21 also use it)
- `update.rs` (the self-update and its settings, U-1 and U-2)

## `tsunagiai-mcp`

It is `src/bin/tsunagiai-mcp.rs`; how to install it is in "Run" of the root `AGENTS.md`.
