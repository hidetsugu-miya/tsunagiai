# Slack

## ワークスペースを追加する

ワークスペースごとに、社内向けの Slack アプリを作ります。
User Token Scopes に `chat:write`・`channels:read`・`groups:read`・`channels:history`・`groups:history`・`im:history`・`mpim:history` を付けてワークスペースにインストールし（Slack の一覧に送信者の名前とアイコンを出すには `users:read`、添付画像を出すには `files:read`、ユーザーグループへのメンションを名前（`@ハンドル`）で出すには `usergroups:read`、リアクションのカスタム絵文字を画像で出すには `emoji:read`、リアクションの付け外しには `reactions:write`、一覧で開いたメッセージや、チャンネルの見出しの「既読にする」を Slack 側でも既読にするには `channels:write` と `groups:write` も付けます。なくても、ほかの機能は使えます。`channels:write` と `groups:write` は、Slack の仕様でチャンネルの管理権限も含みますが、つなぎAIは既読位置の更新（`conversations.mark`）にしか使いません）、発行された User OAuth Token（`xoxp-` で始まる）を、サイドメニュー下部の設定にある「Slack」タブへ貼り付けます。
トークンは Slack に確かめてから、OS の資格情報の保管場所（macOS ではキーチェーン、Windows では資格情報マネージャー）に保存します。
ワークスペースはいくつでも追加でき、同じワークスペースのトークンを貼り直すと置き換わります。
ワークスペースの一覧は、`app_config_dir` の `slack-workspaces.json` に保存されます。

## メールから Slack に投稿する

メールのスレッドを開いているとき、操作の並びの # のボタン（「Slack に投稿」）を押すと、スレッドの右に Slack に投稿するペインが開きます。
もう一度押すか、ペインの右上の × で閉じます。
ペインの上は投稿先のチャンネルのボタンで、下は文を書く欄と「送信」です。
欄は、開くたびに空です。メールの内容は入りません。
ペインを開いたまま別のメールを開くと、欄は空になります（投稿の最中の文は残ります）。

チャンネルのボタンを押すと、追加したワークスペースごとに、トークンのユーザーが参加しているチャンネルの一覧が開きます。
上の欄に文字を入れると、名前にその文字を含むチャンネルに絞ります（Enter で、絞った先頭を選びます）。
一覧を読めなかったワークスペースは、名前の下に理由を出します。
ワークスペースを追加していないときは、一覧は開かず、設定を開くボタンの付いた通知が出ます。
最後に選んだチャンネルは、アプリを終了するまで選んだままで、次にペインを開いたときも、どのメールでも同じです。ファイルには保存しません。

「送信」か ⌘Enter（Windows は Ctrl+Enter）を押すと、そのチャンネルに自分の名前で投稿します。Enter は改行です。
書いた文を、書式を付けずにそのまま送ります（10,000 文字まで。空の文は送れません）。`@here` などは、メンションにしません。スレッドへの返信にはなりません。
チャンネルを選ぶまで、「送信」は押せません。
投稿できたら、欄を空にして、「#{チャンネル名} に投稿しました」と出します。失敗したときは、右下のカードにエラーを出して、文を残します。
投稿するのは、「送信」か ⌘Enter を押したときだけです。このペインでは Claude を使いません。

## Slack の一覧とスレッド

サイドメニューの Slack のアイコンを押すと、Slack の画面が開きます。
画面の左には、Slack 用のサイドメニューがあります。境目をドラッグすると、幅を変えられます。
上に「未読メッセージ」（未読の数つき）と「ウォッチ」の 2 つのボタンがあり、押したほうの一覧を、右の本体に出します（最初は「未読メッセージ」です）。
その下に、ワークスペースごとに、参加しているパブリックとプライベートのチャンネルを名前順に並べます（DM とグループ DM、一覧に出さないチャンネルは出しません）。チャンネルには、未読があれば名前を太字にして、未読の数を出します。
ワークスペースの名前を押すと、そのワークスペースを畳みます。畳むと未読の無いチャンネルが隠れ、未読のあるチャンネルと、履歴を開いているチャンネルは残ります。もう一度押すと開きます。畳んだ状態は、アプリを開き直しても残ります。
一覧は、全ワークスペース分のメッセージを、「未読」「ウォッチ」の 2 つに分けて出します。メッセージが無ければ、その見出しは出しません。
未読は、Slack が覚えている既読位置（`last_read`）より新しいメッセージです。自分の投稿は未読にしません。
未読は、チャンネルごとにまとめ、チャンネルごとに新しい 10 件までを出します（全体の上限はありません）。チャンネルの見出しには、そのチャンネルの未読のメッセージの数（「N 件のメッセージ」）と、2 つのチェックのアイコン「既読にする」が出ます。メッセージはチャンネルの中で古い順に、日付ごとの区切り（今日、昨日、「10月27日（火）」）の下に並びます。既読になったメッセージは、ウォッチしていなければ一覧から消えます。件数は一覧には出さず、サイドメニューの Slack のアイコンにだけ出します。
一覧の上のヘッダーは、スクロールしても残ります。左に「Slack」の見出し、右に、設定の「Slack」タブを開く「一覧に出さないチャンネル」のアイコンがあります。
「既読にする」は、そのチャンネルの既読位置を、最新の未読のメッセージまで進め（一覧に出ていない分も含みます）、そのチャンネルのスレッドの未読の返信も既読にします。スレッドは開きません。`channels:write` か `groups:write` のないワークスペースでは、既読位置は進めず、返信だけを既読にします（進める未読も返信もなければ、ボタンは出ません）。Slack の既読位置は戻せません。送れなかったときは、次の読み込みで未読のまま出ます。
調べるのは、読み込んだチャンネルごとの新しい 20 件までです。それより古い未読は出ません。
未読の件数は、サイドメニューの Slack のアイコンに出ます（20 件を超えると `20+`）。
DM とグループ DM は出しません。入室や退室などのお知らせも出しません。
スレッドへの返信のうち、チャンネルにも送られたものは、一覧に出ます。
未読の 1 行は、送信者のアイコン、名前、時刻、本文、返信の件数（「N 件の返信」。押すとスレッドを開きます）です。ウォッチの行は、送信者のアイコン（ワークスペースの色の点付き）、名前、チャンネル、本文、返信の件数、日付です。
返信の件数の前には返信した人のアイコンを 5 人まで並べ、後ろに「最終返信 15:02」のように最新の返信の時刻を出します。Slack が返信した人を返さないスレッドや、返信した人の名前が読めない（`users:read` が無いなど）ときは、件数だけを出します。
本文は省略せずに全部出します。画像は取得せず、画像だけの投稿は、文字があればその文字を、なければ「（添付ファイル）」を出します。
返信が付いたスレッドで、自分以外の未読の返信があると、行の下に「未読の返信 N 件」のトグルを出し、押すと返信を開閉します（最初は開いています）。数えられない長いスレッドは「未読の返信あり」です。ここで読んでも Slack 側のスレッドの未読は消えません（Slack にスレッドの既読位置を書く API がないためです）。このアプリが覚えている位置までを既読として扱います。
本文の `:tada:` のような標準の絵文字は、一覧とスレッドの詳細で絵文字（🎉）として出します。ワークスペース独自の絵文字は、本文では `:name:` のまま出します（リアクションでは画像で出します。下の「リアクション」を見てください）。
ユーザーへのメンションは、そのユーザーのプロフィール（`https://{ワークスペース}.slack.com/team/{ユーザー ID}`）へのリンクになり、押すと既定のブラウザで開きます。コードの中のメンションは文字のままです。
ユーザーグループへのメンションは、一覧とスレッドの詳細で `@ハンドル` と出します（リンクにはなりません）。ハンドルを読むには `usergroups:read` が要り、なければ、またハンドルが分からないうちは「@不明」と出ます。
Todo にしたかの印は付けません。添付の画像も、一覧には出しません。
行を開くと、そのメッセージとそれより古いメッセージが、そのチャンネルで既読になります（`channels:write` と `groups:write` があるときは Slack 側も既読にします）。
サイドメニューのチャンネルにマウスを乗せると右端に丸にマイナスのアイコンが出て、押すとそのチャンネルを一覧に出さないようにします。スレッドは開かず、Slack 側の既読も変えません。Slack のミュートとは連動しません。
すぐ後の通知の「元に戻す」か、設定の「Slack」タブの「一覧に出さないチャンネル」の「戻す」で元に戻せます。隠したチャンネルは `slack-hidden.json` に ID だけを保存し、読み込みません。
行にマウスを乗せると、しおりのボタンも出ます。押すと、その行のスレッドをウォッチします。ウォッチしたメッセージは「ウォッチ」の段にだけ出て、「未読」の段には重ねません（未読なら太字です）。ウォッチの行は、しおりが常に出ていて、押すと外します（通知の「元に戻す」で戻せます）。
ウォッチの行は、外すまで一覧に残ります。スレッドの最初のメッセージを出し、前に開いたあとの新しい返信（自分の返信は除く）があれば「新しい返信 N 件」を出します（長いスレッドで数えられないときは「新しい返信あり」）。行を開くと、この表示は消えます。
ウォッチは、チャンネルを一覧に出さなくしても残ります。読めなくなったスレッド（削除された、チャンネルを抜けた）の行は、読めないことを示して残り、外せます。
ウォッチしたスレッドの ID は `slack-watched.json` に保存します（ワークスペース、チャンネル、スレッドの `ts` と、最後に開いたときの最新の返信の `ts`）。本文、名前、アイコンは保存せず、起動後に Slack から読み直します。ウォッチの件数に上限はありませんが、1 回の読み込みで確かめるのは、確かめたのが古いものから 20 件までです。
未読の返信を読んだ位置は、`slack-thread-seen.json` に ID と `ts` だけを保存します（新しいほうから 500 件まで）。ウォッチしていないスレッドの未読の返信は、1 回の読み込みで 20 件のスレッドまで調べます。動きのないスレッドは、前に調べてから 1 時間たつまで調べ直しません。
アプリのウィンドウが見えている間は、Slack の画面を開いていなくても、Slack の許す間隔（1〜2 分。すべてのワークスペースが「[一覧をすぐに更新する](#一覧をすぐに更新する)」でつながっている間は 5 分）で自動で読み直し、画面の位置は動かしません。
1 回の読み込みで調べるチャンネルは、1 つのワークスペースにつき 40 までです。それより多いときは、まだ読んでいないチャンネルと、読んだのが古いチャンネルから順に、何回かに分けて読みます。読み切るまで、一覧の上に「残り N チャンネルを読み込み中」と出ます。
画面を開き直したときは、前の読み込みから間もなければ、読み直さずに今の一覧を出します。
読めなかったワークスペースと、トークンに足りないスコープは、画面の右下のカードに出ます（足りないスコープはオレンジの帯の警告で、「設定を開く」のボタンが付きます）。読めたメッセージと、前に読めた分は、そのまま出ます。
メッセージはメモリにだけ置き、保存しません。

未読のメッセージは、どの画面でも、下のフッターのベルを押すと開くペインにも、未読のメールと混ぜて新しい順に並びます。
行にマウスかフォーカスが乗っている間は「既読にする」（押しても何も変わらないときは出ません）と「ウォッチ」のボタンが出て、押すと行はペインから消えます。行を押すと、Slack の画面でそのスレッドを開きます。一覧の行を押したときと同じで、既読位置も進みます。

行を押すと、一覧がそのスレッドの詳細に替わります。
詳細は、メッセージを古い順に出します。送信者のアイコン、名前、時刻、本文（文字として出し、URL だけがリンクになります）です。
本文の書式は、Slack と同じ書き方のものを描きます。太字（`*太字*`）、斜体（`_斜体_`）、取り消し線（`~取り消し~`）、インラインコード（`` `コード` ``）、``` で囲んだコードブロック（長い行は横にスクロール）、`>` で始まる行の引用です。
記号は語の境目でだけ効くので、`snake_case` や `2*3*4` はそのまま出ます。閉じていない記号も、そのまま出ます。
コードの中は、書式も絵文字も変えません。HTML のタグは、書いてあるとおりの文字で出します。URL は、太字などの中でもリンクになります（コードの中ではリンクにしません）。
ボットやアプリの投稿のブロックと添付のカードでも、Slack の書式（`mrkdwn`）の文字は同じように描きます。
ラベル付きのリンク（Slack の `<URL|ラベル>`）は、ラベルをリンクにして出します。ラベルの太字なども効きます。http と https のアドレスだけで、それ以外は文字のまま出します。
ボットやアプリの投稿の、押せないボタンと、セレクトなどのメニューは出しません。そのメッセージの下に、「Slack で操作する」のリンクを 1 つ出し、押すと、既定のブラウザで Slack のそのメッセージが開きます。一覧とチャンネルの履歴でも同じです。URL 付きのボタンは、今までどおりリンクで出します。
添付の本文が 700 文字以上か改行 5 つ以上のときは、Slack と同じく最初の 5 行（700 文字まで）で畳み、「もっと表示する」で全文を出します。一覧でも同じです。
別のメッセージを共有した投稿では、本文のそのメッセージへのリンクを、URL でなく「メッセージ」というラベルで出します（中身は下の添付のカードに出ます）。
添付のファイルの中身は表示しません。一覧と Claude に送る文章は、これまでどおり書式を付けません。最初のメッセージの後に、「返信 N 件」の区切りが入ります。
添付の画像はサムネイルで出し（取得するまでは枠だけ）、画像でないファイルと取得できなかった画像はファイル名の札で出します。サムネイルと札を押すと、Slack でそのファイルを開きます。
左上の戻るで一覧に戻ります。一覧の位置は残っていて、読み直しもしません。
「Slack で開く」でそのメッセージを Slack で開き、「Todo にする」でスレッドを要約し、タスクの案（名前、説明、期限、追加先のプロジェクト）を確認用のカードに出します（Claude Code が使えて、Todoist に接続しているときだけ出ます）。

下の欄から、スレッドに返信できます。
欄は、下の「チャンネルの履歴と投稿」の投稿欄と同じく、書式つきで書けます（枠の上の段のボタンも同じです）。
欄は 3 行の高さで、6 行まで伸びます。Enter は改行で、⌘Enter（Windows は Ctrl+Enter）か、枠の右下の矢印を押したときだけ投稿します。
投稿できたら、欄を空にして、スレッドを読み直して末尾まで動かし、「スレッドに返信しました」と出します。失敗したときは、エラーを出して文章を残します。
書きかけの文章は、アプリを終了するまで、スレッドごとにメモリに残ります。

### リアクション

スレッドの詳細と、チャンネルの履歴の各メッセージには、本文の下にリアクションが絵文字と数で並びます。誰が付けたかは出しません。一覧、ウォッチ、フッターのペインには、リアクションを出しません。
ワークスペース独自の絵文字のリアクションは、その絵文字の画像で出します。画像を読むには `emoji:read` が要り、なければ、また画像が取得できなければ、`:name:` のまま出します。独自の絵文字の一覧は、メモリにだけ 1 時間置き、画像は、アイコンと同じく Slack の画像サーバーから取得します。
リアクションは、押すと付け外しできるボタンです。自分が付けていないものを押すと付け、自分が付けたもの（枠がアクセント色になります）を押すと外します。数と枠の色は、押してすぐに変わります。失敗したときは、理由を通知に出して、何も変えません。付け外しには `reactions:write` が要り、なくても、リアクションは表示します（押すと、スコープが足りないと出ます）。
リアクションの並びの最後にある「☺+」のボタンで、絵文字のピッカーを開きます。リアクションのないメッセージでは、このボタンはマウスを乗せたときだけ出ます。
ピッカーの上の欄に文字を入れると、名前にその文字を含む絵文字に絞ります（Enter で、絞った先頭を付けます）。絵文字は、「よく使う」（付けた回数の多い順に、ワークスペースごとに 24 個まで。同じ回数なら、あとで使ったものが先です。直近 200 回の使用を、設定フォルダの `slack-emoji-usage.json` に保存します）、「カスタム」（そのワークスペース独自の絵文字）、「標準」の順に並びます。`emoji:read` がなければ、「標準」だけです。
絵文字を選ぶと、ピッカーを閉じてリアクションを付けます。

### チャンネルの履歴と投稿

サイドメニューのチャンネルを押すと、一覧やスレッドの代わりに、そのチャンネルの履歴を開きます。
ヘッダーには、チャンネルの名前（プライベートは鍵のマーク）とワークスペースの名前だけを出します。
履歴は、そのチャンネルの最新の 50 件を、古い順に、日付ごとの区切りの下に出します。それより古いメッセージは出しません。未読の一覧と同じく、DM と入室や退室などのお知らせは出しません。
1 行は、未読の一覧の行と同じです。返信のあるメッセージには「N 件の返信」が付き、押すとスレッドを開きます（戻るで履歴に戻ります）。しおりでスレッドをウォッチもできます。
履歴は最新のメッセージの位置で開きます。サイドメニューのチャンネルを押すと、そのチャンネルは、未読の見出しの「既読にする」を押したときと同じく既読になります。
読むのは、そのチャンネルを押したときと、投稿した後だけです。同じチャンネルをもう一度押すと、読み直します。「未読メッセージ」か「ウォッチ」を押すと、一覧に戻ります。
読めないときは、右下のカードにエラーと「再読み込み」を出します。
履歴の下の欄から、そのチャンネルに投稿できます。
欄は書式つきで書けます。枠の上の段のボタンで、選んだ文字を太字、斜体、取り消し線、リンク、番号付きリスト、箇条書き、引用、コード、コードブロックにします。リンクのボタンでは、URL を書く欄が出て、Enter でリンクにします。
欄は 3 行の高さで、6 行まで伸びます。Enter は改行で、⌘Enter（Windows は Ctrl+Enter）か、枠の右下の矢印を押したときだけ、自分の名前で投稿します。10,000 文字までで、空の文章は投稿できません（空のあいだは矢印を押せません）。
書いた書式は、送るときに Slack の書き方（`*太字*`、`_斜体_`、`~取り消し~` など）に直します。見出しは太字の行になり、表などの Slack に無い書き方は文字のまま送ります。リンクにするのは http、https、mailto のアドレスだけで、それ以外のリンクは文字だけを残します（リンクで `@channel` や人に通知が飛ばないようにするためです）。
投稿できたら、欄を空にして、履歴を読み直して最新のメッセージまで動かします。失敗したときは、エラーを出して文章を残します。投稿している間は、どのチャンネルの矢印も押せません。
書きかけの文章は、アプリを終了するまで、チャンネルごとにメモリに残ります。

### スレッドの Claude Code

スレッドの詳細の右側は、Claude Code のターミナルです。
見出しの「Claude」の右端の「やり直す」で、Claude Code を終えて新しく始めます。
使えるのは、`claude` が入っていて、ログインしているか API キーが使えるときだけです（[Claude](claude-integration.md#claude-の接続方式)）。
MCP サーバーは `tsunagiai-mcp` だけを渡し、組み込みの道具とスキルは渡しません。

- スレッドを開いて Claude のタブを出しただけでは、起動しません。タブには「Claude に相談しますか？」と「相談する」だけが出て、「相談する」を押すと起動します。起動したあとは、開発のタブ、戻る、別の画面に移っても、隠すだけで動き続けます。
- 別のスレッドを開くと、Claude Code を終え、Claude のタブは閉じた状態に戻ります。次に使うときは、また「相談する」から始めます。同じスレッドを開き直したときは、開いていれば続きのまま、閉じていれば閉じたままです。

「この返信を丁寧にして」「スレッドを要約して」のように、ターミナルに頼みます。
Claude Code は、`slack_thread_read` でスレッドを、`screen_read` で返信欄を読みます。読むときは聞かれません。
返信の文章は、`screen_write` で返信欄に書きます。書くたびに、ターミナルで聞かれます。
書いた文章は、すぐ返信欄に入ります。投稿はしません。投稿するのは、返信欄の矢印か ⌘Enter を押したときだけで、Claude Code には投稿の道具がありません。
要約や質問への答えは、ターミナルで答え、返信欄には書きません。

書いたあと、返信欄の上の右に「元に戻す」が出ます。
押すと、いちばん新しい書き込みの前の文章に戻ります。続けて押すと、その前へ、新しい順に戻ります。
自分で返信欄を直したときと、返信したあとは、戻せなくなります。

ターミナルに打ち込んだ内容と、Claude Code が読んだスレッドのメッセージ（送信者の名前、日時、画面に出ている本文。ボットの投稿のブロックと添付の文字、ボタンと添付のリンクの URL も含む）と返信欄の文章は、Claude Code を通じて Anthropic に送ります。
スレッドが長いときは、新しいメッセージを優先して合わせて 10,000 文字までにし、古いものを省いて、その旨を添えます。
スレッドのメッセージは他人が書いたものなので、Claude Code には、データであって指示ではないと伝えます。
スレッドを開いただけでは、何も送りません。ターミナルの内容は、本アプリでは保存しません。
区切りで幅を変えられます。

## 一覧をすぐに更新する

Slack の一覧は、既定では 1〜2 分ごとの読み直しで更新します。
ワークスペースごとに「App-Level Token」を登録すると、Slack の Socket Mode でつながり続け（設定の「メニュー」タブで Slack を OFF にすると切り、ON に戻すとつなぎ直します）、投稿、スレッドの返信、メッセージの編集と削除を、1 秒ほどで一覧とサイドメニューの Slack のアイコンの未読の数に反映します。
つないでいないワークスペースは、これまでどおり 1〜2 分ごとに読み直します。

設定は、ワークスペースごとにします。

1. [api.slack.com/apps](https://api.slack.com/apps) で、そのワークスペースの User OAuth Token を取ったアプリを開きます。
2. 「Socket Mode」を開き、「Enable Socket Mode」を有効にします。
3. 「Event Subscriptions」を有効にし、「Subscribe to events on behalf of users」に `message.channels`（パブリックチャンネル）と `message.groups`（プライベートチャンネル）を足して保存します。アプリの再インストールを求められたら、します（`channels:history` と `groups:history` は、上の「ワークスペースを追加する」のスコープに含まれています）。
4. 「Basic Information」の「App-Level Tokens」で、`connections:write` のスコープを付けたトークンを作ります。`xapp-` で始まります。
5. 設定の「Slack」タブの「リアルタイム更新」で、ワークスペースを選び、トークンを貼って「登録」を押します。

登録するとき、Slack に確かめてから、OS の資格情報の保管場所（macOS ではキーチェーン、Windows では資格情報マネージャー）にワークスペースごとに保存します。画面には出しません。
行には、つないでいる状態が出ます。「未登録」「接続中」「つながっている」「つなぎ直し中」のどれかです。行のリンクのアイコンのボタンで、トークンを消してつなぐのをやめます（Slack のアプリは残ります）。

- つながっている間も、一覧は 5 分ごとに読み直します。イベントで来ないもの（ほかの端末でチャンネルを読んだこと）は、この読み直しで反映します。
- 切れたときは自動でつなぎ直します（1 秒から 60 秒まで、間隔をのばしながら）。つなぎ直したときは、切れていた間の分も合わせて、一覧を読み直します。
- 同じチャンネルをイベントで読み直すのは 10 秒に 1 回まで、1 つのワークスペースでは 1 分に 20 回の呼び出しまでです（Slack の呼び出し制限に、一覧の読み直しの分を残すためです）。超えた分は捨てず、あとでまとめて読みます。
- 一覧に出さないチャンネル、ウォッチ、スレッドの未読の返信の扱いは、これまでと同じです。
- トークンを Slack が受け付けなくなったときは、トークンを消して「未登録」に戻します。
- ワークスペースの接続を解除すると、そのワークスペースの App-Level Token も消えます。

## Sentry の通知を操作する

Sentry の通知が Slack に届くワークスペースでは、スレッドの詳細から、Sentry の issue の状態と担当者を変えられます。
ワークスペースごとに、Sentry の Personal Token を設定します。
使えるのは Sentry Cloud（`sentry.io`）だけです。自分で立てた Sentry にはつながりません。

1. Sentry の [Personal Tokens](https://sentry.io/settings/account/api/auth-tokens/) のページで、トークンを作ります。スコープは `event:write`（状態と担当者を変える）、`org:read`（トークンを確かめる）、`member:read`・`team:read`・`project:read`（担当者の候補を読む）です。
2. 設定の「Slack」タブの最後の「Sentry」のカードで、ワークスペースを選び、トークンを貼って「追加」を押します。カードの「?」にも、ページとスコープが出ます。

追加するとき、Sentry に問い合わせて使えるトークンかを確かめてから、OS の資格情報の保管場所（macOS ではキーチェーン、Windows では資格情報マネージャー）にワークスペースごとに保存します。使えないトークンは保存せず、理由を出します。
画面には、トークンの末尾 4 文字と「接続済み」だけが出ます。ごみ箱のアイコンで、確認のあとにトークンを消せます。ワークスペースの接続を解除すると、そのワークスペースの Sentry のトークンも消えます。
どのワークスペースにトークンがあるかは、設定フォルダの `sentry-connections.json` にワークスペースの ID だけを保存します。

トークンを保存したワークスペースでは、スレッドの詳細に出る Sentry の通知（issue へのリンクと、Resolve、Archive、Unresolve のボタンのあるメッセージ）のボタンを押せます。

- 「Resolve」と「Archive」は、押すとダイアログが開きます。Sentry と同じ選択肢から選んで、「Resolve」か「Archive」を押すと送ります。Resolve の選択肢は Immediately、In the next release、In the current release です。Archive は Until escalating、Until 10 events、Until 100 events、Until 1000 events、Forever です。「キャンセル」、Esc、暗い所を押すと、何も送らずに閉じます。
- 「Unresolve」は、押すとすぐ送ります。
- 担当者のメニューは、押すと、その issue のプロジェクトのチーム（「Teams」）とメンバー（「Members」）を Sentry から読み、検索欄つきの一覧を開きます。文字を打つと、名前にその文字を含むものに絞ります。選ぶとすぐ担当にします。読むのは最初の 100 件までです。一覧は保存しません。
- 送っている間は、ボタンが押せません。送れたら「Sentry に送りました」と出して、スレッドを読み直します。断られたら、理由を出します（トークンが正しくない、スコープが足りない、issue が見つからないなど）。スコープが足りないときは、足りないスコープの名前も出ます。

Sentry のトークンは、押したときだけ、`sentry.io` に送ります。ほかのサーバーには送りません。
一覧とチャンネルの履歴には、ボタンを出しません。「Slack で操作する」のリンクが出ます。
トークンのないワークスペースの Sentry の通知も、同じです。

## Slack のメッセージを要約して Todo にする

Todo 画面の追加欄に Slack のメッセージの URL（`https://{ワークスペース}.slack.com/archives/{チャンネル ID}/p{数字}`）を貼ると、ボタンが「要約する」に変わります。
押すと、そのメッセージのスレッド全体（返信のリンクでも、スレッドの親のリンクでも同じです）を Slack から読み、Claude Code の CLI（`claude -p`）で要約します。
スレッドが 1 回に渡せる 10,000 文字に収まらないときは、スレッドの最初のメッセージ（2,000 文字まで）、押したメッセージ（4,000 文字まで）、最新の返信（合わせて 3,000 文字まで）を本文のまま使い、途中のメッセージは、終わりに近いものから何回かに分けて要点にまとめます（時間がかかりすぎたり、途中で失敗したりしたときは、残りは使いません）。
要約に含まれなかったメッセージがあれば、案のページに「N 件のメッセージは要約に含まれていません」と出ます。
押したメッセージが長くて切られたときは、案のページに「対象のメッセージは長いため、先頭だけを要約しました」と出ます（1 件だけのスレッドで 10,000 文字を超えたときも同じです）。
処理中と失敗は、一覧の上の行に出ます。
要約が済むと、Todo 画面の中にタスクの案のページが開きます。
案の上の行には、元のワークスペースと、元のメッセージの先頭の 1 行（入らない分は「…」）、右端に「Slack で開く」が出ます。「Slack で開く」は、そのメッセージを既定のブラウザで開きます。
ページの左に名前と説明（要点の短い箇条書き）、右にプロジェクト、日付（メッセージに期限があれば入っています）、ラベルの枠があり、名前、説明、日付、プロジェクトを直せます。
期限は、チップを押すと開くカレンダーで選ぶか、文字で入力します。
追加先の初期値は、Claude が推奨したプロジェクトで、「推奨」と出ます。
推奨がなければ、貼ったときに開いていたプロジェクトです（「今日」ならインボックスです）。
「今日」で貼った案は、推奨の有無に関係なく、期限が空のタスクの期限が今日になります。
Slack の URL は直せず、右下の追加ボタン（＋）を押したときに説明の末尾に付きます。
追加ボタンを押すまで Todoist には何も作りません。左下の「破棄」か見出しの左の戻るボタンを押すと、何も作らずにページを閉じて一覧に戻ります（Esc では閉じません）。
名前の欄で Enter を押すか、ページの中で ⌘Enter（Windows は Ctrl+Enter）を押しても追加できます。
案がいくつもあるときは、1 つずつ順に開きます。

- 使えるのは、`claude` が入っていて、`claude auth login` でログインしているとき、または API キーが使えるときです（「[Claude の接続方式](claude-integration.md#claude-の接続方式)」）。状態は、設定の Claude タブとサイドメニューのアバターに出ます。
- メッセージを読むには、トークンに `channels:history`・`groups:history`・`im:history`・`mpim:history` のスコープが要ります。足りないワークスペースは、設定で「権限が不足」と出ます。
- Slack のメッセージとそのスレッドの、送信者の ID と本文のテキスト、Todoist のプロジェクトの ID と名前の一覧、要約のしかたの指示は、要約のため Claude Code 経由で Anthropic に送ります。要約のとき、モデルには道具も MCP サーバーも渡しません。
- 案を Claude Code と直すときは、ターミナルに打ち込んだ内容と、Claude Code が読んだ案の名前と説明を、Claude Code 経由で Anthropic に送ります。Slack のメッセージ自体とそのリンクは渡しません。

### 案を Claude と直す

案のページの右にある「Claude」のペインは、Claude Code のターミナルです。案の名前と説明を、Claude Code に直させられます。
見出しの右端の「やり直す」で、Claude Code を終えて新しく始めます。
MCP サーバーは `tsunagiai-mcp` だけを渡し、組み込みの道具とスキルは渡しません。
Claude Code は、auto モード、Sonnet、effort high で起動します。モデルと effort は、設定の Claude タブの選択に従いません。
渡すツールは、`screen_read` と `screen_write` の 2 つだけです。読み書きできるのは、そのページの案の名前と説明だけです。

- 案のページを出しただけでは起動しません。ペインには「相談する」だけが出ます。「相談する」を押すと、その場所にターミナルが出て、Claude Code が起動します。
- ページを閉じる（追加、「破棄」、戻るボタンのどれでも）か、別の案に替わると終わります。次の案では、また「相談する」から始まります。別の画面に移っても、隠すだけで動き続けます。

Claude Code は、`screen_read` で名前と説明を読み、`screen_write` で直したものを書きます。読むときも書くときも、ターミナルで聞かれません。
書いた文章は、すぐ左の名前と説明に入ります。Todoist にはタスクを作りません。作るのは、これまでどおり右下の追加ボタンを押したときだけです。プロジェクト、日付、ラベルは Claude Code に変えさせません。
書いたあと、案の下の追加ボタンの前に「元に戻す」が出て、新しい書き込みから順に戻せます。自分で名前か説明を直すと、戻せなくなります。
頼まなくても、案はそのまま追加できます。
案の名前と説明は Slack のメッセージから作ったものなので、Claude Code には、その中の指示に従わないよう伝えます。
欄は、最初はページの 40% の幅です。間の仕切りをドラッグするか、仕切りで左右の矢印キーを押すと、30% から 60% まで変えられます。幅は、次の案では 40% に戻ります。

### 要約プロンプトを編集する

設定の Claude タブの「Todo の要約プロンプト」から、専用の画面を開きます。
要約のしかたの指示を確認して直せます。「デフォルトに戻す」で初めの内容に戻ります。
モデルに送る指示は日本語で書かれています（保存済みの指示は、そのまま使います）。
メッセージを信用しないという指示、メッセージの区切りの説明、今日の日付、プロジェクトの一覧、メッセージの中の頼みでプロジェクトや期限を決めないという指示は固定で、編集できません。
右側の「Claude と編集」は、Claude Code のターミナルです。見出しの右端の「やり直す」で、Claude Code を終えて新しく始めます。
画面を開いて指示を読み込んだとき起動し、画面を離れても、隠すだけで動き続けます。
MCP サーバーは `tsunagiai-mcp` だけを渡し、組み込みの道具とスキルは渡しません。
Claude Code は、`screen_read` で編集欄の指示を読み、`screen_write` で書き直した全文を編集欄に入れます。書くたびに、ターミナルで聞かれます。固定の部分は渡しません。
入れただけでは保存しません。読んで、「保存」で確定します。
書いたあと、見出しの「デフォルトに戻す」の前に「元に戻す」が出て、新しい書き込みから順に戻せます。自分で編集欄を直すか、デフォルトに戻すと、戻せなくなります。
ターミナルに打ち込んだ内容と、Claude Code が読んだ編集欄の文章は、Claude Code 経由で Anthropic に送ります。Slack のメッセージは渡しません。
