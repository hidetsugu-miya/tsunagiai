# issue にする依頼

オーナーがこのセッションで、次の直しを issue にするよう頼んだ。作者はオーナーで、新しい issue である。

- 内容：Todo 画面のプロジェクト見出しの右に、そのプロジェクトの未完了タスクの数を小さく出す（新しい機能、画面の変更）。
- 決定：オーナーは 2 案のうち案 A（見出しの右に灰色の小さな数字）を選んだ。
- 検証：コードを確かめ、`ts/todo.ts` と `src/style.css` だけで作れると分かった。要件の節は `requirements/tasks.md` の T-5 に足す。
- 計画：`ts/todo.ts`、`src/style.css`、`requirements/tasks.md`、`e2e/specs/todo.e2e.ts` の順に直す。
- スクリーンショット：オーナーは今の Todo 画面のスクリーンショットを渡し、「これが今の画面で、見出しの右に数を足したい」と言った。写っているのはオーナー本人の実際のプロジェクトとタスクで、次のとおり。
  - プロジェクト：「北斗物流 基幹刷新」、「青葉クリニック 予約システム」
  - タスク：「北斗物流 基幹刷新」の下に「在庫テーブルの移行手順を書く」と「夜間バッチの停止時刻を倉庫と決める」、「青葉クリニック 予約システム」の下に「予約枠の重複を直す」
- プロトタイプ：まだ作っていない。案 A のモックを HTML にして、開発タブのプレビュー（`preview_open`）でオーナーに見せ、受け入れてもらってから issue にする。この依頼では、そのモックの HTML を作るところから始める。
- ポイントは 3 のつもり。
